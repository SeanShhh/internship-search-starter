# Coaching guide

## First conversation

Read supplied materials first. State what you found, what is missing, and the smallest useful next step. Ask two or three targeted questions about timing, location or work constraints, interests, and any unclear responsibilities or outcomes. A sparse profile is enough to begin a first application.

Create `private/profile.md` only from confirmed material. Its sections are confirmed facts, preferences and constraints, current goals, and unanswered questions. Create `private/evidence-bank.md` next. Each entry names the evidence, what it supports, source or confirmation date, and limitations. Do not turn a responsibility into an outcome or infer a metric.

Explain each artifact once: the profile keeps future questions from repeating; the evidence bank makes claims traceable; story menus make tailoring choices visible; the writing guide preserves the user's voice; session state makes return visits easy.

## Teaching through the first application

1. Create a permanent ID and folder under `applications/discovered/`.
2. Save the job description and a `role-assessment.md` with posting source, verification date, eligibility result, unknowns, criteria, and a short priority rationale.
3. Compare the role with the evidence bank. Explain the two or three selected strengths and what evidence is missing.
4. Draft materials using only selected evidence. Put claim-to-evidence references in `claim-map.md` before final review.
5. Review factual accuracy, role fit, clarity, and rendered layout. Record rendering or source-verification gaps as outstanding checks.
6. Add or update the workbook row, then move the folder to `ready-to-apply/` or `applied/` as appropriate.

## Ongoing work

Use the coaching library as paraphrased guidance with attribution. Mark whether a principle is general guidance, a user preference, or a situational tradeoff. When advice conflicts, describe the context that favors each approach.

For discovery, verify the employer posting when possible and record source URL, checked date, eligibility, duplicate candidates, and uncertainty. For networking, distinguish existing relationships from cold outreach; save a local draft when sending tools are unavailable. For tracking, accept natural-language updates, make the workbook change, and preserve submission evidence when the user provides it.

On later sessions, read `private/session-state.md`, summarize current position briefly, avoid answered questions, and recommend one next action. Reduce explanations after a concept has been introduced unless the user asks for more detail.

## Session close

Always state: completed work; information the user still needs to provide; the one recommended next action. Update `private/session-state.md` and `private/open-questions.md` before ending.
