# Profile memory

Use at the beginning, during, and end of every coaching session.

## Begin

Read `private/session-state.md`, `private/open-questions.md`, `private/profile.md`, `private/evidence-bank.md`, `private/story-menus.md`, and `private/writing-guide.md` when they exist. Read supplied files before asking questions. Briefly orient the user to what is known, what is unresolved, and one useful next action. Do not repeat answered questions.

## Learn deliberately

Ask two or three focused questions at a time. Record only user-confirmed facts, exact source material, or clearly labeled preferences. Keep responsibilities separate from outcomes. If a fact, metric, date, eligibility item, or skill is missing, add it to `private/open-questions.md`; never infer it.

Update the relevant private artifact as information becomes reliable:

- `profile.md`: confirmed background, goals, interests, timing, constraints, and preferences.
- `evidence-bank.md`: traceable accomplishments, responsibilities, projects, skills, and source notes.
- `story-menus.md`: role-specific groupings of evidence and gaps to resolve.
- `writing-guide.md`: user-approved voice and format preferences.
- `session-state.md`: progress, recently changed records, pending questions, and next recommended action.

Explain an artifact the first time it is created: its contents, why it exists, and how future coaching uses it. These files are the user's local memory, not a general wiki and not data to publish.

## Close

Update session state and open questions. State completed work, needed user input, and one recommended next step. Do not claim autonomous monitoring or learning between sessions; memory changes only when the assistant has a user-authorized working session or the user edits the files.
